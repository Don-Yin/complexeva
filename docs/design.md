# design decisions

- The next release is 0.3.0, because the three measure fixes change numerical results and the API is not yet declared stable (1.0 waits for the API and packaging decisions). Changes are listed in `CHANGELOG.md`; the version number in the package metadata is agreed but not yet bumped.
- No backward compatibility is kept: the removed `measures`/`signal` modules are not restored and old numerical behaviour is not offered behind options. Downstream projects such as rotation-1 track the newest release, and old versions remain on PyPI for anyone who needs them.
- The package is MIT-licensed (copyright 2024-2026 Don Yin, `LICENSE`), the shortest permissive licence common in scientific Python. The licence file exists; declaring it in the package metadata is agreed but not yet implemented.
- Every measure is imported from the top level (`complexeva.hfd(x)`); the `complexeva.sequence` subpackage is removed because the package only covers 1D series. Implemented; tests, `examples/validate.py` and README use the new imports.
- Unexported and duplicate code is removed: the Hilbert transform/frequency variants, the string-returning `time_series_to_binary`, the numba binarisation helper (now plain numpy), unused `**kwargs`, hard-coded shebangs and `__main__` benchmarks. `hfd_hilbert` and `lempel_ziv_hilbert` remain and compute the measure on the Hilbert envelope. Implemented; outputs on a test signal are unchanged.
- 0.3.0 adds no new measures: it ships the fixes and cleanup quickly so rotation-1 can recompute with it. New measures (sample/permutation entropy, DFA) are added later only when needed, each with a known-answer test.
- Packaging is a single `pyproject.toml` with hatchling (replacing `setup.py` and `requirements.txt`): version 0.3.0, MIT licence, `requires-python >=3.14`, runtime dependencies only `numpy`, `scipy`, `numba` (unpinned so pip picks a mutually compatible set), optional `test` extra with `pytest`. The wheel ships only `complexeva/`; the sdist adds tests and docs files. `validate.py` moved to `examples/` because it needs matplotlib. Implemented; a clean Python 3.14 venv installing the built wheel passes all tests and `twine check`.
- CI (`.github/workflows/workflow.yml`, name kept because the PyPI trusted publisher is registered for it) runs `ruff check` and `pytest` on Ubuntu and macOS with Python 3.14 for pushes and PRs, then builds and `twine check`s; only a `v*` tag that equals `v` + the `pyproject.toml` version publishes to PyPI through the `pypi` environment. The black auto-commit step is removed. Implemented; ruff and pytest pass locally, the workflow has not run on GitHub yet.
- User documentation is the README only (install, one example, a table of each measure's output, parameters and reference); no docs site, because six functions do not justify one. Implemented; the README example runs and gives the stated values.
- Old material is deleted from the working tree: the plots made with the D - 1 HFD, the rotation-1 `observations/` notebooks, and `public/test-images/` (screenshots from Varley 2020, a copyright risk once public). `examples/validate.py` can regenerate correct plots. The files remain in git history.
- `hfd` raises `ValueError` unless 2 <= `k_max` <= len(X) // 2; 0.2.3 crashed with `ZeroDivisionError` or returned NaN for series shorter than about 2 * `k_max`. Implemented and tested in `tests/test_higuchi.py`.
- `hfd` defaults to `k_max=10` (was 64). In a simulation with exact Davies-Harte fBm (H 0.2-0.9, N 100-1200, 300 repetitions), bias was below 0.07 for every `k_max` while RMSE grew with `k_max` (N = 261: 0.053 at 10, 0.105 at 64); with fGn, which resembles BOLD, separation of H = 0.5 from 0.9 peaked at `k_max` 6-10 (N = 261: d = 5.6 at 10, 3.4 at 64). This agrees with Accardo et al. 1997 (best estimate at `k_max` = 6 for Weierstrass and fBm segments of N = 50-1000) and Porcaro et al. 2020 (`k_max` = 12 on 50-volume fMRI windows). Wanliss & Wanliss (2021 preprint, doi:10.21203/rs.3.rs-756319/v1) fit larger values from mean error only, for N >= 1000, so variance is not in their criterion. 10 also matches antropy and keeps short series (N >= 20) valid. The 2025 Information Fusion review (doi:10.1016/j.inffus.2025.102936) advises a larger K from Weierstrass signals with lambda = 10, but there the estimate oscillates with `k_max` (log-periodic L(k)), so larger is not reliably better; with lambda = 2, 10 is near-unbiased. The `L_m(k)` formula matches Higuchi 1988 section 2. Users should report `k_max`. Implemented.
- Git history was rewritten with `git filter-repo` to remove `public/test-images/` (Varley 2020 screenshots) from every commit, then force-pushed to `main` (old tip 25c2262, new tip d2fd2fa; 33 commits, trees otherwise identical). A scan of all history found no secrets, only hard-coded `/Users/donyin` shebangs. Old commits stayed reachable by SHA, so the GitHub repository was deleted and recreated under the same name (no stars, forks, issues or PRs to lose), which made them return 404 at once instead of waiting for a support purge; the `pypi` environment was recreated. Done.

- `hfd` returns the standard Higuchi fractal dimension D (white noise ≈ 2, Brownian ≈ 1.5, sine ≈ 1) with no legacy switch; 0.2.3 returned D − 1 because L_m(k) lacked the final `/k` and dropped one increment. Old values remain reproducible by pinning `complexeva==0.2.3`. Implemented and tested in `tests/test_higuchi.py` (literal-formula reference and known dimensions); agrees with `antropy.higuchi_fd` to 4 decimals.
- `lempel_ziv` counts the final, unfinished copied component as Kaspar & Schuster (1987) do (`"0000000000"` gives 2); 0.2.3 omitted it and undercounted by 1 on about 87% of random strings. Implemented and tested in `tests/test_lempel_ziv.py` (known strings, random-string reference, numeric binarisation); matches `antropy.lziv_complexity(normalize=False)` on 2000 random strings.
- `lempel_ziv(..., normalize=False)` keeps the raw integer count by default; `normalize=True` returns c\*log2(n)/n over the binary sequence length n (n - 1 for `method="diff"`, 0.0 when n <= 1), so random input scores about 1 and lengths become comparable. The Hilbert variants forward the option. Implemented and tested in `tests/test_lempel_ziv.py`; matches `antropy.lziv_complexity(normalize=True)` to 1e-15.
- `lyapunov_exponent` is rewritten as the Rosenstein et al. (1993) largest exponent (delay embedding, nearest neighbour outside a Theiler window that defaults to the mean period, slope of mean log divergence over `trajectory_len` steps, divided by `dt`), keeping `tau`, `m`, `dt` and adding `min_tsep`, `trajectory_len`, `fit_offset`. Rewriting was chosen over deletion because a correct numba version was quick; 0.2.3 averaged one-step log distances, so it depended on signal amplitude and gave 8.36 for the logistic map. Implemented and tested in `tests/test_lyapunov.py` (logistic map ln 2, Henon 0.419, sine about 0, scale invariance, `dt`); agrees with `nolds.lyap_r(fit="poly")` to 4 decimals.
